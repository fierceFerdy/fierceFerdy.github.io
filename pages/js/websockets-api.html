Websockets and APIs

In this chapter, we will explore the concepts of WebSockets and APIs in JavaScript. We will learn how to establish real-time communication using WebSockets and we'll learn a bit about APIs.

The core difference

APIs and WebSockets are two different ways to communicate with a server. APIs typically use HTTP requests to fetch data, while WebSockets provide a persistent connection for real-time communication.

API (HTTP)

  • Request → response → connection closes
  • Client always starts the conversation
  • Stateless (each request stands alone)

An API is like sending letters; each request is independent and the connection closes after the response. It's cooler than it sounds.

Great for:

  • Fetching data (GET /scores)
  • Submitting forms (POST /login)
  • Protecting resources behind authentication

WebSocket

  • PersistentPersistent: continuing to do something, or lasting. In this case; "The connection remains open" connection
  • Server can push data to the client
  • Stateful (connection remains open)

A WebSocket is like a phone call; the connection stays open and both parties can communicate in real-time. Built for instant updates.

Great for:

  • Chat
  • Live dashboards
  • Multiplayer games
